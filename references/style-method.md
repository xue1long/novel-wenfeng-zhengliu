# 文风提取方法

一次整合提取按五个维度记录候选，不需要五个 Agent 或五套脚本。

1. **叙述视角与口吻**：视角稳定性、叙述距离、态度和信息揭示方式；排除来源角色性格。
2. **句式与段落节奏**：句长变化、断句方式和段落节拍；量化结论记录样本数与计数口径。
3. **场景构造与转场**：场景开合、动作/感官信息编排和节奏变化；不复制事件顺序。
4. **对白与潜台词**：对白密度、轮次节奏、言外之意和区分声音的方法；不复制台词或人物口吻。
5. **修辞与意象组织**：比喻、反复、对照和意象的结构作用；只提炼机制，不保留独创意象或专有措辞。

## 取样与证据

- 按开篇、人物出场、对白、日常、冲突、转折和结尾等场景类型检查覆盖；按自然边界取样，单段默认不超过 5,000 字符。
- 先记录留出场景的定位，再提取。文件型来源使用原始文件 SHA-256、章节/场景 ID 和 LF 规范化后的行列号；源文件改变后重做定位。模型按段落、时间地点变化和行动连续性推断场景边界；低信心边界应缩小样本或标 `limited`，不要求用户手工确认。聊天粘贴文本用输入 ID、场景 ID 和段落序号定位，不声称有文件哈希或精确行列。
- 留出文本不能作为机制证据或提取输入。若全文已在模型上下文中，标记留出污染，不得称为独立验证。
- 证据摘录只留在私有账本，每条最多 200 个 Unicode 码点。Style Bundle 仅存定位引用，不存原文。

## 机制卡

每条候选至少写出：

- `mechanism_id` 和维度；
- 一条抽象规则，以及在新故事中可执行的动作/检查项；
- 适用范围（全局、跨场景观察或局部）；
- 证据定位和反例；
- 模型判定状态及理由。

跨章节规律至少由 3 个场景、2 个章节支持；低于此门槛时只能限定为局部观察或标记 `limited`，不能外推为全书规律。可迁移的局部规则至少要有 2 个独立场景支持。

## 自动判定门槛

每条候选由模型独立按同一份检查表判定，不等待用户逐条审批：

- **`model_approved`**：定位可回查；有至少 3 个场景、2 个章节的支持；规则可操作且不重叠；反例能界定何时不使用；范围没有超过样本覆盖；通过内容隔离检查。
- **`model_limited`**：至少 2 个独立场景支持，但证据只覆盖一个窄场景/章节或只支持局部用法；规则仍可执行、安全且有反例。写入 Skill 时必须保留局部限制。
- **`excluded`**：少于 2 个独立支持场景、定位不可靠、反例推翻该规则、无法转成具体动作、与其他规则重复，或包含来源特有内容。

只有 `model_approved` 和 `model_limited` 可以进入写作 Skill；没有任何机制通过时不生成 Skill，并报告缺少的证据。模型评审不是独立的人类验证，需如实标注证据范围和评测限制。

区分稳定规律、叙述者口吻、题材惯例与特殊场景技巧。交叉维度不需要争抢唯一归属；给机制指定一个主要维度，必要时用次级标签标记。
